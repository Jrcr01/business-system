Stage D3 (Payables): mock-up for approval

What this is: the Payables screens on the new Django system, drawn with its real styling. Nothing works yet; names and numbers are examples.
Proposed split, each with its own sign-off:
  • D3a, the daily work: Order statements (the batches), one batch with its invoices and credit memos, printing one batch, Add data, Payables due (screens 1–5).
  • D3b, the bulk tools: invoices from photos/PDFs and from a spreadsheet, many batches from one Excel file, printing many batches in one PDF, the vendor SOA matcher (screen 6).
What changes from Streamlit:
  • The invoice and credit-memo grids become a list with Edit on each row and an Add row: two people never overwrite each other (the second is told the invoice changed).
  • A batch's Checks tab shows the checks (read only) until D4 (Paying) brings issuing, parking, numbering and corrections.
  • Payables due's Calendar comes with D4 and Everything owed with the reports (D8); until then they open in Streamlit.
Same rules otherwise: the due date is worked out from the supplier's terms, a duplicate invoice number is refused, a batch closes by itself once its checks cover it, and reopening or cancelling asks first.

D3b · the bulk tools inside Order statements
6 · Bulk tools (each is its own page off Order statements)
  • Invoices from photos / PDFs: upload one file per invoice; the system reads the doc ref, date and amount; you check and correct each line before anything is saved. (Reads offline on this computer; the server will need the same reader installed.)
  • Invoices from a spreadsheet: download the CSV template, upload, check the lines, add. Option: give the batch its OS number in the same step.
  • Many batches from one Excel file: one sheet = one new batch. Pick the supplier for each sheet (guessed from the sheet name), then create them all.
  • Print many batches: since the last check print / today / last 7 days / all; untick any; A4 or thermal; a summary page in front; one combined PDF.
  • Vendor SOA matcher: upload the supplier's statement of account; see matched, missing in AP, amount mismatches and omitted from the SOA.

Each reads the file first and shows what it found; nothing is saved until you press the final button, as in Streamlit.
